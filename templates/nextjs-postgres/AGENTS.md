# Project conventions

This app was generated by CapHub Studio. Keep to these conventions so it keeps working.

## Stack
- **Next.js 16 App Router** (`src/app`), React 19, TypeScript (strict), Tailwind CSS v4.
- **Postgres** via **Drizzle ORM** (`drizzle-orm/node-postgres`). Schema in `src/lib/db/schema.ts`; import `db` from `@/lib/db`.
- **Auth** is built in: email + password, bcrypt hashes, signed JWT session cookie (`src/lib/session.ts`).
  - Server code: `getCurrentUser()`, `requireUser()`, `requireAdmin()` from `@/lib/auth`.
  - Roles: `user` and `admin`. The first account to sign up becomes `admin`. Admins manage roles at `/admin`.
  - `src/proxy.ts` redirects signed-out visitors away from `/dashboard` and `/admin`. Add new private route prefixes to its `matcher`, and still call `requireUser()`/`requireAdmin()` in every private page and server action.

## Environment
- `DATABASE_URL` and `AUTH_SECRET` are provided by the platform. Never hardcode secrets.
- The dev server runs `next dev` on port 3000. Schema changes are applied with `npm run db:push` (runs automatically on start).
- Type-check with `npm run typecheck` (checks `src/` only; ignores Next's generated `.next/` types).

## Rules
- Mutations: use **Server Actions** (`"use server"`) or Route Handlers in `src/app/api`. Validate all input with **zod**.
- Authorize on the server for every read and write of user data; never trust IDs from the client.
- Server Components by default; add `"use client"` only for interactivity. Never import `@/lib/db` or `@/lib/auth` from client components.
- Route params and `searchParams` are Promises in Next 16: `const { id } = await params`.
- Add dependencies with `npm install <pkg>` (don't hand-edit versions).
- Keep `src/app/api/health/route.ts` working — the platform uses it.
